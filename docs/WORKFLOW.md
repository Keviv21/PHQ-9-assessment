# End-to-end assessment workflow

The [editable Excalidraw diagram](diagrams/assessment-workflow.excalidraw) and [SVG preview](diagrams/assessment-workflow.svg) describe the current workspace. Shapes are native editable objects; the diagram contains no real patient information or secrets.

1. **Prepare the catalogue.** Import the supplied JSON through `scripts/assessments/import-catalogue.mjs`. Normalize definitions while preserving response types, limits, options and conditional rules. Store reviewed runtime definitions and hashes in `data/assessments/catalogue.json`; unavailable content stays visible with an explanation.
2. **Select or add a patient.** The workspace lists the imported NeuroTwin patient and four samples. Selecting a patient exposes their stored history summary; added details persist in `patients`.
3. **Obtain suggestions.** Opening the review step requests history-based recommendations. A matching context cache is reused; otherwise Gemini compares the redacted summary with catalogue metadata. Provider/response failures allow retry or manual selection. Suggestions are clinician aids, not diagnoses.
4. **Refine the choice.** The doctor can use structured clinical review without Gemini or a temporary Gemini conversation. Its messages and suggestions are not saved. All catalogue entries remain searchable; a runnable leading suggestion is selected automatically unless the clinician has made a manual choice.
5. **Confirm a prescription.** The selected assessment is linked to the patient in `assessment_prescriptions`. This does not start the assessment automatically.
6. **Choose language and response mode.** On the assessment page, choose one of nine supported languages and Chat, Voice or On-screen. Translation validation covers full questions, options and controls while retaining canonical IDs. A failed translation must not silently produce mixed-language content. A session freezes the definition, language and mode.
7. **Answer the questionnaire.** On-screen answers go through the HTTP API; live chat/voice uses Gemini via the app's WebSocket bridge. Clear answers save without repeated confirmations. Ambiguous responses may require clarification. Optional camera sharing is explicit.
8. **Validate and save each response.** Server validation enforces source types, limits, valid choices, skip rules and conditional applicability. Written feedback is not numerically scored. Invalid answers remain unsaved; stale revisions produce conflicts. Valid changes persist with an audit trail, and the next applicable question is shown.
9. **Review and complete.** The participant can correct responses before saving the completed session. Every required applicable question must be answered. Current imported questionnaires produce response records without invented scores; scored historical definitions retain their own rules.
10. **Read the result.** The patient record exposes saved sessions, report viewing/download, browser Print / Save as PDF, and analytics. Graphs use stored visits and valid source scoring only. Reopening a session/report keeps its original questionnaire wording and language.

History recommendations and translations use separate persistent caches. Temporary doctor messages, full session transcripts, audio and video are not stored. Only brief response summaries may accompany canonical saved session answers. See [architecture](ARCHITECTURE.md) for table details and compatibility routes.
